In this assignment I learned when to use each way of sending data with requests: the Azure endpoints (sentiment, entityrecognition) take a form with data=, the AI endpoints (systemone, chat completions) take a JSON body with json=, and model settings like model and reasoning_effort go in the query string with params=. I learned that raise_for_status() stops the code at the line that caused an HTTP error (401 for a missing or wrong key, 429 for going over the 150-request limit, 5xx for a server problem), where otherwise the error comes back as a normal-looking dict and fails later as a KeyError. I keep my key in .env and read it with get_api_key(), so it never ends up in a commit. I learned that caching is a pattern: if the cache file exists, json.load it, and otherwise call the API once per review, add review_id, and json.dump the raw response. This separates extract (sentiment_step, entities_step, which touch the network) from transform (sentences_table, opinions_table, entities_table, which only reshape saved JSON), so I could debug the tables from cache/ or the fixtures without spending calls. I also learned why the pipeline combines opinion mining and entity recognition: in T3, opinion mining correctly separates "seating" (positive) from "music" (negative) inside one sentence, but it misses Pete, Tally and Otto because they have no assessments, and entity recognition finds them. My biggest struggle was opinions_table. json_normalize with record_path="sentences", meta=["review_id"] and record_prefix="sentence_" worked for sentences_table, but a target's relations point to its assessments by a ref string, so I needed nested for loops and int(ref.split("/")[-1]) to look up the right item in that sentence's assessments list. I am still shaky on what meta copies from the parent document versus what record_prefix renames, and on why the decision model's request has to be byte-for-byte identical to hit the portal's cache. I also learned the idea behind retrieval-augmented generation: pandas builds the facts (summarize_items as a pivot table plus the engineered net column), evidence_for retrieves only the matching mentions, and the language model only writes from those facts, which is why the page shows st.warning and skips the model when nothing matches. My next step is to take the cached sentiment JSON for T3 and try to rebuild opinions_table with a single pd.json_normalize call (record_path=["sentences", "targets"] plus meta), then compare it with my nested-loop version to see exactly what json_normalize cannot do. I will also call classify_mentions twice with the same mentions, then once with them reordered, and time each call to see the cache behavior I don't yet understand.
